12. [권고12] 사이트/버전 의존 항목에 플래그를 달아라. M1.1 item4(Core/PLC/Host 연결 램프)와 M1.3 item2(용어집)는 MXA본에만 있는 근거인데 기준본을 v04로 권고한 S1의 핵심 항목에 들어 있다. M6.3을 '선행 모듈'로 두고 그 판정 결과에 따라 S1~S5 항목이 켜/꺼지는 구조로 명시하면 '없는 화면을 가르치는 사고'를 막는다는 M6.3의 설계 의도가 실제로 작동한다.

## 미해결 결정사항(open_questions — 발주자 판단 대기)
- Q: 교육 대상 사이트와 OCS 버전을 어디로 확정하는가 — v04(한국어 원판) / 중문통합본 / MXA본(RCP 표기) 중?

  추천: v04를 기준본으로 확정하고, MXA본 고유 화면 4종은 Config 시트의 Site/Version 값에 따라 켜지는 '옵션 모듈'로 분리 운영. 교육 2주 전 대상 사이트에서 10개 메뉴 탭을 실제로 펼친 캡처 1세트를 받아 존재 여부를 실측하는 것을 전제 조건으로 둔다.
- Q: 맵 도구를 무엇으로 확정하고, L3(c) RailTool 교육의 권한 범위를 어디까지 허용하는가 — Winlay / LayOut Designer / RailDesignTool 2 중 현 사이트 도구는? 교육생이 실 운영 DB에 MapLoad를 수행해 보게 할 것인가?

- Q: 교육 대상자를 Role Track으로 나눌 것인가, 전원 L3까지 끌고 갈 것인가 — 나눈다면 트랙별 목표 레벨은?
  왜: L3가 38항목(28%)이고 대부분 실제 로그 샘플과 실습 환경을 요구한다. Rose 절체와 MapLoad는 라인을 세울 수 있는 조작이어서 전원에게 실습시키는 것이 적절하지 않을 수 있다. 반대로 전원을 L1에 묶으면 타 사이트에 로그 분석 역량이 남지 않는다. 교육 공수·평가 공수·권한 부여가 모두 여기서 갈리는데 자료로는 알 수 없다.
  추천: 3트랙 권고 — Operator(목표 L1, S1~S5 중심, 48점 범위), Engineer(목표 L2, 전 섹션 L1+L2 = 98항목), Senior(목표 L3, 136항목 전부 + Rose·MapLoad 실행 권한). Engineer Profiles 시트에 Role Track 열을 신설해 사람마다 목표 레벨을 명시하고, 완료율은 목표 레벨 범위 기준으로 계산한다.
- Q: 합격선과 레벨 구간을 어디로 정하는가 — LCS의 <50% Trainee / 51~65% L1 / 66~90% L2 / 91%+ L3을 그대로 쓸 것인가?
  왜: OCS는 배점이 S8(19점)·S5(13점)·S2(12점)에 몰려 있어 L1만 보유한 인원의 이론적 최고점이 38점대다. LCS 구간을 그대로 쓰면 L1을 완벽히 숙지한 신입이 'Trainee'로 떨어진다. 반대로 구간을 낮추면 L3 미보유자가 L2로 인증된다. 이건 평가 철학의 문제이고 발주자만 답할 수 있다.
  추천: 구간을 레벨별 이수율 기반으로 바꿀 것을 권한다 — Level 1 = L1 35항목 중 90% 이상, Level 2 = L1 90% + L2 63항목 중 80% 이상, Level 3 = L2 80% + L3 38항목 중 70% 이상 + Prohibited-Ops Gate 및 L3 Practical Gate 통과. 섹션 100점 총점은 '참고 지표'로 남기고 레벨 판정의 1차 기준에서 빼는 편이 OCS 배점 편중에 맞다.
- Q: 실습 환경을 어디까지 제공받을 수 있는가 — ①XCom Simulator + Simulation.exe 기반 교육용 OCS 1세트 구축 가능 여부 ②실제 로그 샘플(Comm/PntOccupy/Order/SECS)의 타 사이트 반출 승인 ③Rose 절체 실습이 가능한 시간대

  추천: 최소안 — ①교육용 서버 1대에 XCom Simulator + Simulation.exe로 상위·차량 없는 OCS 1세트 구축(설치 기준서 4장 절차) ②로그는 차량번호·카세트ID·IP를 마스킹한 30분 분량 Case Bank로 반출 신청 ③Rose 실습은 테스트 서버 2노드로 대체하고 운영 서버 절체는 참관만. 이 3개가 확보되지 않으면 S8·S9를 '이론+샘플 판독'으로 격하하고 Practical Gate를 유예해야 한다.
- Q: 이번 교육의 산출물로 '자료에 없는 문서'를 새로 만들 것인가 — ①알람별 조치문(ErrTag 2,277행의 ErrActionText가 전부 ErrText와 동일) ②원인 특정 이후 복구 절차서 ③Rose 단독 실행 후 이중화 복귀 절차서 ④정기 점검 체크시트 양식

- Q: 타 사이트 배포 시 민감 정보 마스킹 범위를 어디까지 가져가는가 — 장비 접속 ID/PW(RestAPI·Clean Vehicle 자료에 평문 존재), 서버·AP IP 대역, AP 배치, 사이트 호스트명(RCP-DB01, AGV03/AGV04, STOTA20100)

## 자료 갭(data_gaps)
- 원인 특정 이후의 복구(조치) 절차 전반 — 로그분석 자료는 '원인 특정'까지만 간다. PntOccupy 점유 고착을 어떻게 해제하는가, PlcCommLog가 WaitConnect일 때 무엇을 재시작하는가, 멈춘 Order를 어떤 순서로 푸는가가 어느 문서에도 없다. L3(a)의 '처리' 절반(S8 M8.2~M8.4)이 비어 있어 현장 엔지니어 인터뷰로 새로 작성해야 한다.
- Rose 단독 실행 후 이중화 복귀(원복) 절차 — 단독 실행으로 내려가는 길만 11슬라이드로 있고, NIC IP 원복 → Rose 서비스 기동 → Group Bring In 역순이 전혀 없다. S9 M9.3의 절반이 공백이며 현장 사고 위험이 가장 크다.
- RailDesignTool이 Export한 JSON을 OCS 실 시스템에 반영하는 절차와 JSON 스키마 — 어느 서버·어느 경로에 두는지, Core가 언제 읽는지, 재기동이 필요한지, 이중화 양 노드에 각각 넣어야 하는지가 전 자료에 없다. L3(c)의 후반부(S7 M7.3)가 비어 있다. 탐색기 캡처에 보이는 'MapData' 폴더의 정체도 미설명.
- 32종 로그의 실제 저장 경로·폴더 구조·파일명 규칙·로테이션 정책 — RcpLogPath 예시(D:/Program/Log)와 D:/XComLog만 확인되고 로그 이름 ↔ 실제 파일 위치 매핑표가 없다. Core-Event / Core-TaskMgr도 '기록되는지 확인'만 지시되어 있다. S8 M8.1 실습 설계의 선행 조건.
- 수 GB 로그 실무 취급법 — grep/PowerShell 검색 절차, 시간 범위 추출, 여러 로그 병합 타임라인 작성법이 Select-String -NotMatch '_SNMP' 한 줄뿐이다. S8 L3 실습 17항목이 전부 이 기술을 전제한다.
- 화면별 권한 매핑표 — Guest<User<Operator<Engineer<Manager 5단계가 있다고만 하고 어느 화면이 어느 권한부터 보이는지의 표가 없다. Role Track과 계정 권한을 연동하려면 현장 실측이 필요하다(Safety ID 미로그인 시 Save 버튼이 안 보인다는 단서 1건만 확인).
- 파라미터 기본값·권장 범위·상하한 표와 변경 적용 시점(즉시 vs 프로세스 재시작) 일괄 규칙 — 사용예시에 '80', '600', '5000' 같은 값만 산발적으로 있어 '이 값은 이 범위에서만 만져라'를 가르칠 근거가 없다. 변경 이력 추적 화면/로그도 없다(14.8 UseVehicleScreenName의 'UI를 끄고 다시 킨다' 1건만).
- PLC 설비 알람의 한글 원인·조치 설명 — ErrTag SYSTEM 1,574행과 STATIONALARM 26행에 설명이 전무하다. ErrorDescription.xlsx의 Description은 441행(대부분 VEHICLE)에만 있고, CPS Erec_UnderVoltage·FailOver_MC_Short 같은 비트명은 전기 지식 없이 해석 불가. S8 M8.4의 설비 알람 역조회가 '번호 찾기'까지만 가능.
- ErrTag 현행본 확정 — 260103_ErrTag_L30.xlsx(2,277행/21 ErrType)와 ErrorDescription.xlsx(2,403행/19 ErrType)가 서로 다른 개정판이고 STATIONALARM(8105~8130 vs 5000~5273)·PING(120 vs 112)·SYSTEM(1,574 vs 1,500) 대역이 불일치한다. 어느 쪽이 운영 반영본인지 자료로 판별 불가. 확정 전까지 코드 대역표를 교재로 확정할 수 없다(S2 M2.3).
- 실화면 캡처 전 세트 — 매뉴얼과 setup 가이드(캡처 118장)가 '□ 버튼 누르면 Delete/Clear/Insert 조작화면이 나타남' 식으로 아이콘 이미지에 의존해 서술하는 곳이 많아 텍스트만으로 버튼을 특정할 수 없다. S1~S5의 L1 교재는 실화면 캡처를 새로 떠 아이콘-기능 매핑표를 만들어야 한다.
- 대상 사이트 네트워크 구성도와 AP 배치도(위치별 채널 할당표) — CommT의 PNT 편중으로 음영 구간을 특정해도 '그 구간 담당 AP가 몇 번이고 채널이 몇인지' 찾을 표가 없다. 네트워크 자료도 2019 BOE(서브넷 255.255.254.0)와 2026 Micron(255.255.252.0)이 혼재. AP Troubleshooting Export 파일을 어떻게 읽는지도 비어 있다.
- EQ Group / EQ Tag(SNMP·REST 감시) 화면의 입력 필드 구성 — 전부 스크린샷 이미지이고 사용자 매뉴얼 v04에 해당 절이 없는 신규 기능이라 실습 교안을 새로 만들어야 한다. ErrTag의 AP 12대·HUB 6대와 SNMP 목록의 AP 8대 불일치도 확인 필요.
- Clean Mode의 동작 의미 — 조작 순서(Object>Vehicle Clean On/Off, CycleMove Unuse Pause/TotalCycleMove)만 있고 Clean Mode를 켰을 때 오더 할당·경로·타 차량 간섭이 어떻게 달라지는지 설명이 전무하다(S3 M3.2).
- 정상 기준값 13항목의 사이트 환산 — 표본이 Micron AATT Taichung(차량 44대·PLC 8대) 1시간이라 타 사이트 차량 대수·레이아웃 규모에 맞춘 환산식이 없다. S8 M8.5의 이상 판정 기준이 반쪽이 된다.
- Winlay 조작 절차 — AutoBlock 생성 주체이자 MDB 작성 도구로 반복 언급되는데 사용법 문서가 없다. RailDesignTool(LayOut Designer)과 대체 관계인지 병행인지도 불명이라 S7에 Winlay 항목을 세우지 못했다.
- Secom 프로그램의 실체 — 로그분석 매뉴얼은 로그 생성 4주체에 Secom을 넣는데 setup 가이드·설치 기준서는 Core/MCS_IF/PlcDriver/RCPGT 4개만 말한다(document.xml 전문 검색 0건). MCS_IF와의 역할 분담 확인 전까지 S6 M6.1을 문서 근거가 있는 5요소로만 구성했다.
- PIO(E84) 핸드셰이크 타이밍 차트와 Timeout 설정 위치 — Interlock Time Error·PIO Timeout이 계속 언급되는데 신호 타이밍 정의가 어느 문서에도 없다. 165CH와 E84 경로 다이어그램도 이미지라 미확인. S8 M8.4의 E84 알람 판독(ErrEvent 500~720)이 명명 규칙 암기 수준에 머문다.
- 로그 ON/OFF·수집 범위를 바꾸는 파라미터 매핑표 — 어떤 파라미터가 32종 로그 중 어느 것을 켜는지의 대응표가 없다(LogTrafficData/LogRecvData/LogDebuggingData/WriteCommPacket 4개만 확인).
- 정기 점검 주기와 체크시트 양식 — CPU/RAM/HDD와 DB 12항목을 '주기적으로'라고만 하고 일/주/월 주기와 기록 양식이 없다. S9 M9.1을 평가에 연동하려면 이번 교육에서 새로 만들어야 하는 산출물.
- Rose 로그의 실제 경로·파일명과 Failover 판정 기준값 — 콘솔에 Log 확인 영역이 있다는 것만 있고 Heartbeat 타임아웃·복제 지연 임계값 숫자가 '3600s까지 3회' 하나뿐이다. 영문 매뉴얼 서비스명(MirrorService 등)과 현장 서비스명(RoseHAService 등)·중문 UI 대응표도 새로 만들어야 한다.
- RCPHMI.txt 미해결 이슈 8건 중 7건의 최종 원인 — PushWeight 밀어내기 미동작, Cluster Point Insert 실패, Layout Check 9992~9999 경고, Line Out 후에도 S6F11 반복 등. L3 분석 훈련 케이스로는 가치가 높으나 정답이 없어 Case Bank에 '정답 없음 / 분석 과정 연습'으로 성격을 명시해야 한다.
